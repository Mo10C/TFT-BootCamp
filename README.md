# クラウドハッシュテイル校 TFT ログイン式リーダーボード

URLを踏むとまず **ログインページ** が開き、
① Riot ID（サモナー情報＋TFTランク取得）② Discord（アイコン・名前・**ロール**取得）
の2ステップを済ませた人だけがボードに入場できます。
入場した人は自動で選手登録され、**Discordロールを使ったフィルタ・組卓**ができます。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `login.html` | 入口。Riot ID検証 ＋ DiscordログインOAuth |
| `home.html` | **HOME**。ログイン後の着地点。メニュータイル＋ツール |
| `boards.html` | 大会一覧・新規作成（公開範囲の指定込み） |
| `index.html` | 本番ボード。組卓・順位入力・全体順位 |
| `editor.html` | 管理コンソール（**管理者専用**・タブ式） |
| `lp.html` | **LPランキング**。メンバー一覧＋LP推移グラフ＋増減 |
| `schedule.html` / `members.html` | 準備中ページ（枠だけ） |
| `core.js` | 共通ロジック（セッション / 権限 / Firestore同期 / 得点 / 公開範囲 / HOME設定 / Riot API） |
| `home-common.js` | HOME系ページの共通処理（テーマ・プロフィール・権限バッジ） |
| `ui.css` | HOME系ページの共通スタイル |
| `config.js` | 設定（Firebase / Worker URL / region / **管理者** / 既定値） |
| `worker.js` | Cloudflare Worker（Riot中継 ＋ Discord OAuth ＋ ロール解決 ＋ `/diag`） |
| `wrangler.jsonc` | Worker のデプロイ設定 |
| `DESIGN-auth.md` | 次フェーズ（Firestoreルールの厳格化）の設計判断メモ |

## 画面のつながり

```
login.html ──▶ home.html ──┬─▶ boards.html ──▶ index.html（ボード本体）
                           ├─▶ schedule.html / members.html / lp.html（準備中）
                           └─▶ editor.html（管理者のみ）
```

`?board=xxx` 付きのURLでログインした人は HOME を経由せず直接そのボードへ入ります。

## 管理コンソールのタブ

| タブ | できること |
|---|---|
| 🏠 HOME編集 | タイトル・メニュータイル（並び替え/表示/準備中/ロール制限）・ツールの編集 |
| 🏆 このボード | 大会名・公開範囲の設定 |
| 🗂 大会の管理 | ボード一覧・切り替え・**削除** |
| 👥 メンバー | 表示名の固定・ランク/ロールの一括再取得・除名 |
| 📈 LP | 比較の基準日の設定・全員のLPを一括記録 |
| 🔌 接続設定 | Worker URL の上書き・接続テスト・**設定診断（/diag）** |
| 💾 データ | JSONバックアップ・復元・結果クリア・初期化 |

HOMEの設定は Firestore の `lboard_index/home` に保存されます（既存のルールで書けるので追加設定は不要）。

## 運営（観戦）ロール

`config.js` の `roles.staffRoleIds` にロールIDを入れると、そのロールの人は**見るだけの人**になります。

- すべての画面を**閲覧できる**（ロックされない）
- 大会の参加者一覧・組卓・全体順位に**入らない**
- メンバー一覧・LPランキングにも**出ない**
- ただし記録自体は残るので、**管理コンソール →「👥 メンバー」→「大会に参加」をONにすれば普通の参加者になる**（本人が再ログインしてもこの設定は消えません）

## Discordに投げる文面の編集

**管理コンソール →「💬 メッセージ」**

| メッセージ | 投稿先 | いつ |
|---|---|---|
| ランクアップのお祝い | 談話室 | 毎日23:45の集計でティアが上がった人がいたとき |
| きょうの予定 | 連絡事項 | 毎朝9:00（予定がある日だけ） |
| 先生スナップショットの結果 | 談話室 | 実施日の23:45 |
| 代表先生の表彰 | 談話室 | 最終回の23:45（結果のすぐあと） |

どれも **見出し → 明細（件数ぶん繰り返し） → しめの一言** の3つでできています。
見出し・しめを空にすると、その行ごと出ません。明細は空にできません（既定に戻ります）。

`{name}` のような差し込みは、編集欄の下のボタンから挿入できます。
編集するとその場で Discord 風のプレビューが更新されます。

保存先は Firestore の `lboard_index/messages`。**保存するまでは既定の文面**が使われます。

## 予定表と当日通知

| 何が | どこで |
|---|---|
| 予定の追加・編集 | 管理コンソール →「🗓 予定表」 |
| みんなが見る画面 | `schedule.html`（HOMEの「予定表」タイル） |
| 当日9:00の通知 | Worker の Cron Trigger `0 0 * * *`（UTC。= 9:00 JST）→ **連絡事項** チャンネル |
| 通知のテスト | 管理コンソール →「🗓 予定表」→「🔔 いますぐ通知してみる」 |

保存先は Firestore の `lboard_index/schedule`。**一度「💾 保存」を押すまでは初期データが表示されているだけ**で、
通知は動きません（Worker は Firestore を見るため）。最初に一度保存してください。

> Cloudflare の Cron 入力欄は **UTC** です。`0 0 * * *` と入れると日本時間の9:00に鳴ります。
> `0 9 * * *` と入れると日本時間の18:00になってしまうので注意してください。

## 先生スナップショット

| 何が | どこで |
|---|---|
| 設定（対象ロール・実施日・ポイント） | 管理コンソール →「🏅 先生スナップショット」 |
| 実行 | 実施日の 23:45 JST（LP一斉集計の直後・Cron `45 14 * * *`） |
| 投稿先 | **談話室**（`DISCORD_ANNOUNCE_CHANNEL_ID`） |
| 手動テスト | 管理コンソール →「🏅」→「いますぐ実行する」／ `/snapshot?key=<CRON_KEY>` |

流れ:

1. 実施日の23:45にLPを一斉集計 → そのLPで対象ロールの人を高い順に並べる
2. 上位4人に 4/3/2/1 pt を配り、結果を談話室へ投稿
3. 最終回（実施日のいちばん後ろ）では、全回の合計ポイント上位4人を
   **「代表先生」**として表彰するメッセージも投稿

> 設定を **一度「💾 保存」しないと動きません**（Worker は Firestore の
> `lboard_index/snapshot` を見るため）。
> 対象ロールを選ばないと「メンバー全員」が対象になります。

## LPランキングの仕組み

### 並び順（セクション）の設定 — 管理コンソールだけで完結します

**管理コンソール →「📈 LP」タブ → 並び順（ロールごと）**

1. **「🔄 Discordのロールを読み込む」** を押す（Worker経由でサーバーのロール一覧を取得）
2. 使いたいロールに **「使う」** のチェックを入れる
3. 行を**ドラッグ**（または ↑↓）で、出したい順に並べる
4. **「💾 保存」**

`config.js` を編集する必要はありません。設定は Firestore（`lboard_index/lp` の `groupOrder`）に保存され、全員に反映されます。

- **見出し名**は変えられます。隣どうしで同じ名前にすると**1つのセクションにまとまります**
  （例: 校長と副校長を両方「校長・副校長」にする）
- **複数のロールを持つ人は「リストの下のほう」のセクションに入ります**
  （校長が生徒ロールも持っている → 校長・副校長に入る）
- どれにも当てはまらない人は、いちばん下の「その他」にまとまります
- 「使う」が1つも無ければ、セクション分けはせず1つの並びになります

> メンバーの側にロール情報が無いと全員「その他」になります。
> その場合は同じ画面の **「👥 メンバーのロール情報を更新」** を1回押してください
> （Riot APIは呼ばないので一瞬で終わります）。

### グラフの見かた（v3.6〜）

- **1人 = 横に長いバンド1本**。左から「順位・アイコン・名前」→「グラフ」→「LPの増減」
- **行をクリックすると大きく開き**、日付とLPの数字まで出ます（もう一度クリックで閉じる）
- **横軸はどの行も共通**で、いちばん上の日付ものさしにそろっています。
  「基準日から」を選ぶと、管理コンソールで指定した**基準日がいちばん左**、今日が右端
  （基準日が未設定のときは「直近30日」表示）
- 縦の幅は既定では人ごとに自動（右はしに「縦◯◯LP」と表示）。
  **「縦をそろえる」**を押すと全員同じ縦幅になり、伸びの傾きをそのまま見比べられます
- **並びはグループが最優先**：`config.js` の `roles.lpGroups` に書いた順（既定: 生徒 → 先生 → 校長・副校長 → その他）で
  見出しを付けて並びます。その中の順番を「現在のLP順／基準日からの伸び順／前日からの伸び順／名前順」から選べます
- グラフに出るのは**記録が残っている日だけ**です。基準日をさかのぼって設定しても、
  その日より前のLPを後から取得することはできません（Riot APIに過去のLP履歴が無いため）


| 何が | いつ記録されるか |
|---|---|
| **毎日23:45（JST）に全員** | Cloudflare Worker の Cron Trigger が一斉集計（`45 14 * * *` UTC） |
| 全員ぶんを今すぐ | 管理コンソール → 📈 LP →「全員のLPを今すぐ記録」（ブラウザから） |
| サーバー側の集計を試す | 管理コンソール → 📈 LP →「🌙 サーバー側の一斉集計を今すぐ試す」（`CRON_KEY` が必要） |

### 毎日の集計に必要な設定（Worker）

| 名前 | 種別 | 値 |
|---|---|---|
| `FIREBASE_PROJECT_ID` | Text | `tft-leaderboard-f6897` |
| `FIREBASE_API_KEY` | Text | config.js の `apiKey` と同じ |
| `RIOT_PLATFORM` | Text | `jp1` |
| `DISCORD_ANNOUNCE_CHANNEL_ID` | Text | **ランクアップのお祝い**を投げるチャンネルID（談話室） |
| `DISCORD_SCHEDULE_CHANNEL_ID` | Text | **予定の当日通知**を投げるチャンネルID（連絡事項） |
| `CRON_KEY` | Secret | `/collect` の手動実行用（任意） |

さらに **Cloudflare → Worker → Settings → Triggers → Cron Triggers** に `45 14 * * *` を登録します。

> ⚠️ **Riotの開発用キーは24時間で失効する**ため、毎日の集計はほぼ必ず失敗します。
> この機能を使うなら **Personal API Key の申請が実質必須**です。

### ランクアップのお祝い

集計時に**ティアが上がった人**を検出して、指定チャンネルへ自動投稿します。

- ティアをまたいだ昇格のみ（GOLD II → GOLD I のような同ティア内は投稿しません）
- 保存済みのティアが無い人（初回記録）は投稿しません（誤爆防止）
- Bot にそのチャンネルへの**メッセージ送信権限**が必要です（`permissions=0` で招待した場合は、チャンネル権限かロールで許可してください）

- 保存先は `lboard_index/lp`（`members` / `hist` / `baseline`）。履歴は日付をキーにした数値です
- LPは**ティアをまたいで比較できるよう通し数値に換算**します（IRON IV 0LP = 0、1ティア = 400、1ディビジョン = 100、マスター以上は 2800 + LP）
- 「前日」は**今日より前の直近の記録**との差。毎日ログインしない人でも比較できます
- 「基準」は管理コンソールで指定した日（合宿の開始日など）からの差。基準日以前の記録が無い人は最古の記録を使います
- グラフの線は**同時6人まで**。色は検証済みのカラーパレットを使い、名前の直接ラベル・凡例・表ビューを併用しているので、色が見分けづらくても読めます

# ★ 権限モデル（v2.1）

`config.js` の `admins` に載っている人だけが編集できます。

| 操作 | 管理者 | 一般プレイヤー |
|---|:--:|:--:|
| ボードの閲覧・全体順位 | ○ | ○ |
| ログイン時の自己登録（ランク・ロール更新） | ○ | ○ |
| **自分の**出欠チェック | ○ | ○ |
| 他人の出欠・出欠の一括操作 | ○ | ✗ |
| 大会名・試合数・卓数の変更 | ○ | ✗ |
| 自動組卓・席の配置・順位入力・⚡自動取得 | ○ | ✗ |
| `editor.html`（管理コンソール） | ○ | ✗（ロック画面） |

## 管理者の指定方法（3通り・併用可）

```js
admins: {
  discordIds: ["123456789012345678"],  // ★最も確実。開発者モード→自分を右クリック→ユーザーIDをコピー
  riotIds: ["Mo10C#819"]               // Riot ID（大文字小文字は無視）
},
roles: {
  adminRoleIds: ["運営ロールのID"]      // このロール保持者も管理者として扱う
}
```

> ⚠️ **3つとも空だと「セットアップ中」とみなして全員が管理者になります。**
> その場合は画面に `⚠️ 管理者未設定` バッジが出ます。必ずどれか埋めてください。

## 権限の実装レイヤー

ボタンを隠すだけでなく、**`core.js` の Store 側で全ミューテーションをガード**しています
（`store.setActor({pid, isAdmin})` が起点）。ガードに弾かれると `window` に
`lb-denied` イベントが飛び、画面側がトーストを出します。

> ⚠️ ただし現時点では **Firestoreのセキュリティルールは緩いまま**です。
> ブラウザのコンソールから直接 Firestore を叩けば書き換えは可能です。
> そこを塞ぐ設計は `DESIGN-auth.md` を参照。

# セットアップ手順

## 1. Discord アプリを用意（1回だけ）

1. [Discord Developer Portal](https://discord.com/developers/applications) → New Application
2. **OAuth2** ページで
   - `CLIENT ID` と `CLIENT SECRET` を控える
   - **Redirects** に `https://<WorkerのURL>/auth/callback` を追加（Workerデプロイ後に確定）
3. **Bot** タブで Bot を作成し `TOKEN` を控える → サーバー（クラウドハッシュテイル校）に招待
   - 権限は不要（ロール一覧の読み取りだけに使用）。招待URL例:
     `https://discord.com/oauth2/authorize?client_id=<CLIENT_ID>&scope=bot&permissions=0`
   - ※ 既存のランク表示Botを使い回してもOK（同じサーバーに入っていれば良い）
4. サーバーIDを控える（Discordの設定→詳細設定→開発者モードON → サーバー右クリック→IDをコピー）

## 2. Worker をデプロイ

```bash
# worker.js と wrangler.jsonc があるフォルダで
npx wrangler deploy

# シークレットを設定
npx wrangler secret put RIOT_API_KEY
npx wrangler secret put DISCORD_CLIENT_ID
npx wrangler secret put DISCORD_CLIENT_SECRET
npx wrangler secret put DISCORD_BOT_TOKEN
```

- `wrangler.jsonc` の `DISCORD_GUILD_ID` にサーバーIDを記入
- `RETURN_ORIGINS` は本番オリジン（`https://mo10c.github.io`）＋ローカル確認用を推奨
- デプロイ後のURL（例 `https://mcc-login-board.xxx.workers.dev`）を
  **Discord Developer PortalのRedirects**（`.../auth/callback`）と **config.js の workerUrl** に設定

動作確認: `https://<Worker URL>/health` が `{"ok":true}` を返せばOK。

## 3. config.js を設定

- `workerUrl`: 手順2のURL
- `firebase`: 既存リーダーボードと同じ値のままでOK（プリフィル済み）
- `platform`: JPサーバーなら `jp1` のまま
- **`admins.discordIds`**: 自分のDiscordユーザーIDを入れる（最優先で設定）

## 4. Firestore ルールに新コレクションを追加

既存プロジェクトを使う場合、`lboards` / `lboard_index` を許可します（Firebaseコンソール → Firestore → ルール）:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /boards/{id} { allow read, write: if true; }        // 既存
    match /board_index/{id} { allow read, write: if true; }   // 既存
    match /lboards/{id} { allow read, write: if true; }       // ★追加
    match /lboard_index/{id} { allow read, write: if true; }  // ★追加
  }
}
```

## 5. GitHub Pages に配置

このフォルダ一式（`login.html` `index.html` `editor.html` `core.js` `config.js`）をリポジトリの任意フォルダへ。
アバター画像を使う場合は `assets/moto-hero.png` も同じ階層の `assets/` に置いてください（無ければ自動で非表示）。

> ポータル（クラウドハッシュテイル校TOOLS）へ載せる場合は、運用ルール通り **ポータルの editor.html からツール追加** で `login.html` へのリンクを登録してください。

## 6. 使い方

1. 共有するのは **login.html のURL**（`?board=大会ID` を付けると大会別）
   例: `https://mo10c.github.io/lboard/login.html?board=camp-2026-08`
2. 参加者は Riot ID確認 → Discordログイン → 入場（自動で選手登録）
3. 主催は組卓 → 対戦 → 結果タブで順位入力 or ⚡自動取得
4. 🏆全体順位が累計ptで自動集計（得点は既存と同じ 1位8pt〜8位1pt）

# よくあるハマりどころ

- **Discordログイン後にエラー**: Redirects の登録URL（`/auth/callback` まで完全一致）と `RETURN_ORIGINS` を確認
- **ロール名が出ない（IDだけになる）**: `DISCORD_BOT_TOKEN` 未設定か、Botがサーバーに入っていない
- **ランクが「ランクなし」**: そのアカウントが今セットでランク戦未プレイ（正常動作）
- **`_nojekyll` 問題**: GitHub Pages では `.nojekyll`（先頭ドット）である点に注意
- **開発キーの期限**: Riot開発キーは24時間で失効。切れたら Worker のシークレットを更新
- **自分が管理者なのにロック画面が出る**: `config.js` の `admins` に自分が入っているか確認。
  Riot ID指定の場合、ログイン時に入力した Riot ID と完全一致（タグ含む）が必要

## v3.5（2026-09）— 組卓のドラッグ&ドロップ／1人1枚のLPグラフ

- **組卓をドラッグ&ドロップ化**（`index.html` + `core.js`）
  - 参加者POPを卓の席へドラッグして配置
  - 席どうしのドラッグで**入れ替え**（同じ卓の中なら入力済みの順位は保持、卓をまたぐと順位はクリア）
  - 参加者バーへ戻すと**席から外す**
  - マウス／タッチ共通（PointerEvent）。タッチは**長押し220ms**で掴む＝ページのスクロールを邪魔しない
  - 従来の「POPをタップ→席をタップ」も残してあります
  - 追加API: `store.moveSeat()` / `store.unseatPlayer()`
- **LPグラフを1人1枚に**（`lp.html`）
  - 全員を重ねた1枚 → メンバーごとのカード。色で人を見分ける必要がなくなりました
  - 「縦をそろえる」トグルで、伸びの傾きの比較モードに切り替え
- **グラフの左端を基準日に固定**（`core.js` に `lpRange()` / `daysBetween()` を追加）
  - `lpSeries(lp, id, {from, to})` で区間指定できるように（数値を渡す従来の呼び方も動きます）
- 管理コンソールの基準日の説明を「グラフの左端」に更新。
  実際の記録開始日が基準日より後のときは警告を出すようにしました
